# SayoHonami_Music · 游戏内点歌台

Minecraft **1.21.11** + Fabric 的多人点歌模组。支持 **QQ音乐 / 网易云** 搜索点歌，
**服务端同步队列**：一个人点歌，所有装了模组的玩家同时听同一首歌。
带 **同步歌词显示** 与 **可拖拽调整的 HUD 位置**。

> 服务端也需要装这个模组。没装模组的原版玩家不会掉线，只是听不到声音（会在聊天栏看到点歌提示）。

## ✨ 功能

| 功能 | 说明 |
|---|---|
| **双平台搜索点歌** | QQ音乐 / 网易云，右上角按钮切换 |
| **服务端同步队列** | 一个人点歌，房间内所有人同步听同一首 |
| **同步歌词** | 自动拉 LRC，HUD 逐行高亮当前句，可选翻译 |
| **面板位置可拖拽** | 音乐信息 / 歌词面板都能拖动，位置存进配置 |
| **房间系统** | 每个房间独立队列，互不干扰；退出重进自动回原房间 |
| **歌单导入** | 粘贴 QQ音乐歌单链接，整张歌单一次性入队 |
| **三档播放模式** | 顺序播放 / 单曲循环 / 随机播放（一轮内不重复） |
| **队列搜索** | 在队列里快速找歌 |
| **会员歌支持** | QQ / 微信扫码登录 + **网易云 Cookie 登录**，Cookie 只存在**你自己的电脑**上 |
| **跨平台兜底** | 一个平台放不了，自动去另一个平台找同名歌 |

**关键设计：服务端不联网、不存音频、不承担流量。**

服务端只做「排队 + 广播进度」，每台客户端自己下载自己播。
好处是服务器不会被音乐平台风控、不需要开额外端口、也不需要部署任何 Node.js 服务。

## 📦 安装

### 客户端

1. 装好 **Fabric Loader 0.19.4+** 与 **Fabric API 0.141.6+1.21.11**
2. 把 jar 丢进 `.minecraft/mods/`
3. 启动游戏

### 服务端（要多人一起听就必须装）

1. 服务端装 Fabric Loader + **Fabric API 0.141.6+1.21.11**
2. 把同一个 jar 丢进服务端 `mods/`
3. 重启服务器

> 单机玩也可以：单人存档里逻辑服务端就在本地，照样能用。

### ⚠️ 升级注意

**客户端和服务端版本必须一致**（自定义数据包格式会变）。
升级时**先删掉旧 jar**，否则 Fabric 会同时加载两个。

## 🎮 怎么用

| 操作 | 说明 |
|---|---|
| **按分号键 `;`** | 打开点歌台（可在「选项 → 按键」里改） |
| 页签「搜索」 | 选平台 → 输关键词 → 回车搜索 → 点歌 |
| 页签「队列」 | 看大家点了什么，点歌名插播、点右侧删除；顶部可搜歌 / 导入歌单 |
| 页签「播放」 | 进度条、暂停/继续、上/下一首、播放模式、清空、音量 |
| 页签「设置」 | 歌词/音量/HUD 开关、字号行数、调整布局、扫码登录、队列上限 |
| 数字键 `1`~`4` | 快速切页签 |

### 调整面板位置

1. 按 `;` → 「设置」页 → 点 **「调整布局（拖拽）」**
2. 屏幕上出现两个框（**音乐信息** / **歌词**），**直接用鼠标拖动**
3. 松手即自动保存，点 **「完成调整 ✓」** 退出

另外三个按钮：「歌词吸附到面板下方」「恢复默认位置」「重新加载歌词」。

> 拖动时面板会被限制在屏幕范围内，不会拖丢。位置写在配置里，重进游戏还在。

### 登录（想放会员歌 / 高音质才需要）

设置页有三个按钮：

- **「登录方式：QQ / 微信 / 网易云」** —— 点击循环切换
- **「QQ音乐登录（扫码）」/「微信登录（扫码）」** —— 点击开始扫码
- **「网易云：粘 Cookie 登录」** —— 点击显示获取 Cookie 的步骤

> 登录状态只存本地 `config/sayo-honami-music.json`，**不会上传到任何地方**。
> 三种登录方式**各自独立保存**，互不干扰。

#### QQ / 微信（扫码）

二维码显示在**主界面外侧**，用手机扫 → 确认 → 显示「登录成功」。

#### 网易云（Cookie）

网易云没有提供「一张二维码图片」的接口（它的二维码是网页里现画的），
所以这里用 Cookie 登录。**怎么拿 `MUSIC_U`：**

1. 浏览器登录 https://music.163.com/
2. 按 `F12` → **应用 / Application** → **Cookie** → `https://music.163.com`
3. 找到 **`MUSIC_U`**，复制它**整行**（或只复制值都行）
4. 粘到设置页的 Cookie 输入框 → 点 **「导入」**

登录后能拿到**更高音质（320kbps / 无损）**，而且部分「未登录返回 404」的歌也能放了。

> 也可以直接把整串 `Cookie: a=1; MUSIC_U=xxx; b=2` 粘进去。
> 导入时会联网验证一次，Cookie 无效会明确告诉你原因。

### 服务器指令

| 指令 | 权限 | 说明 |
|---|---|---|
| `/symus status` | 所有人 | 查看当歌台状态 |
| `/symus room join <房间名>` | 所有人 | 进入房间 |
| `/symus room leave` | 所有人 | 回默认房间 |
| `/symus room list` | 所有人 | 列出所有房间 |
| `/symus room cleanup` | OP 2 级 | 清理没人的空房间 |
| `/symus limit <数字>` | OP 2 级 | 改服务端队列上限（最大 10000） |
| `/symus login <cookie>` | **OP 4 级** | 服务端登录（QQ 的 `qm_keyst` 或网易云的 `MUSIC_U`，全服免登录） |
| `/symus logout` | **OP 4 级** | 服务端退出登录 |

> 服务端登录后，所有玩家点歌都由服务端解析播放地址，**客户端不需要自己登录**。
> 也可以在服务器控制台直接敲（控制台天然是 4 级权限）。

## ⚙️ 配置文件

`config/sayo-honami-music.json`（客户端和服务端**各一份**）：

```jsonc
{
  "defaultSource": "qq",          // 默认平台：qq / netease
  "volume": 0.7,                  // 音量 0~1
  "crossSourceFallback": true,    // 放不了自动换平台找同名
  "audioEnabled": true,           // 游戏内播放开关

  "showHud": true,                // 显示音乐信息面板
  "musicPanelX": -1,              // 面板 X 坐标，-1 = 用默认角标
  "musicPanelY": -1,
  "hudPosition": "top_right",     // 默认角标

  "showLyrics": true,             // 显示歌词面板
  "lyricsPanelX": -1,
  "lyricsPanelY": -1,
  "lyricsLines": 3,               // 歌词行数 1~7
  "lyricsScale": 0.9,             // 歌词字号 0.6~1.4
  "showTranslation": true,        // 显示翻译

  "allowPlayerRequest": true,     // 服务端：是否允许普通玩家点歌
  "maxQueueSize": 20,             // 服务端：队列上限（最大 10000）
  "requestCooldownSeconds": 10,   // 服务端：点歌冷却
  "openKey": 59                   // 快捷键（GLFW 码，59 = 分号）
}
```

**注意**：客户端和服务端的配置是**两个不同的文件**。
队列上限由**服务端**决定，改客户端那份没用 —— 要用 `/symus limit` 或设置页的按钮（需要 OP）。

## ⚠️ 已知限制

1. **VIP 歌能不能放，取决于你自己的账号**。未登录时平台只给免费歌的地址。
   登录后如果仍然放不了，说明该账号没有对应会员权益，此时会自动走「跨平台兜底」。
2. **热门版权歌（周杰伦等）在 QQ音乐通常拿不到地址** —— 平台限制，不是 bug。
   模组会自动去网易云找同名版本播放。
3. **接口随时可能变**。模组用的是网页版公开接口，音乐平台改版后可能需要更新模组。
4. **服务端不播放声音**，音频始终由各客户端自己下载 —— 玩家不需要开额外端口，
   但需要能访问音乐平台。
5. **歌词也可能取不到**（部分歌曲平台没收录），不影响播放。

## 🔧 疑难排查

### 按分号键卡死 / 界面打不开

**第一步：看日志**。用记事本打开：

```
<你的游戏目录>/.minecraft/logs/latest.log
```

搜索 `SayoHonami` 或 `YueMusic`，先确认有没有 `客户端初始化完成`。

**排查用的通用开关**（`config/sayo-honami-music.json`）：

```jsonc
{
  "showHud": false,        // 关掉音乐信息面板
  "showLyrics": false,     // 关掉歌词面板
  "audioEnabled": false    // 关掉游戏内播放（其它功能照常）
}
```

### 放歌没声音

按顺序检查：

| 检查项 | 怎么做 |
|---|---|
| 模组是否加载 | 日志里有没有 `客户端初始化完成` |
| 游戏内播放是否开着 | 设置页「游戏内播放」开关 |
| 音量 | 播放页「音量 +/−」按钮；**服务端和客户端各自独立** |
| 这首歌是否放得了 | 看聊天栏提示；会员歌可能需要登录 |
| 服务端是否装了模组 | 不装服务端模组，队列无法同步 |

## 🛠️ 开发

### 环境要求

| 项 | 版本 |
|---|---|
| Minecraft | 1.21.11 |
| Fabric Loader | 0.19.4 |
| Fabric API | 0.141.6+1.21.11 |
| Yarn mappings | 1.21.11+build.6 |
| Fabric Loom | 1.18.3（插件必须用 `net.fabricmc.fabric-loom-remap`） |
| Java | **编译目标 21；构建期需要 JVM 25** |

> ⚠️ `gradle.properties` 里的 `org.gradle.java.home` 已被注释掉（那是作者本机路径）。
> 你需要自己指定 JDK 25：在 `%USERPROFILE%\.gradle\gradle.properties` 里加一行，
> 或者用环境变量 `JAVA_HOME`。

### 构建

```bash
./gradlew build        # 产物在 build/libs/
./gradlew runClient    # 开发环境启动客户端
```

### 代码结构

```
src/main/java/com/yue/music/
  api/        MusicProvider 接口 + QQ/网易云实现 + QQ扫码登录 + LrcParser + HTTP 工具
  model/      MusicTrack / PlayUrl / MusicSource / Lyrics
  audio/      AudioPlayer（单线程流式播放）+ PcmSource（解码成 44.1k/16bit/立体声 PCM）
  server/     ServerQueue（队列/进度/播放模式）+ MusicServer + RoomManager + MusicCommand
  net/        MusicNetworking（自定义包定义）
  config/     MusicConfig
src/client/java/com/yue/music/client/
  YueMusicClient        按键/事件/HUD 注册
  audio/ClientAudio     客户端状态机（点歌、同步、播放）
  lyrics/LyricsClient   歌词获取/缓存/时间轴
  ui/MusicScreen        点歌台界面
  ui/MusicHud           游戏内两个面板
  ui/PanelEditor        面板拖拽与位置保存
```

### 音频架构要点

- **播放器是单线程常驻的**：整个 `AudioPlayer` 只有一个播放线程，
  新请求会替换掉旧请求（靠"代次"标记），**结构上不可能两路声音叠加**。
- **进度用单调时钟**（`System.nanoTime()`）计算，不受系统校时影响。
- **不用 OpenAL**：Minecraft 自己用 OpenAL，模组再开一套会在 `OpenAL.dll` 里互相踩导致崩溃。
  改用 JDK 自带的 Java Sound，和游戏声音引擎完全隔离。

### 测试

见 [`_ref/e2e/`](_ref/e2e/README.md)（纯 Java 小程序，不依赖游戏启动器）。

### 扩展新平台

实现 `MusicProvider`（搜索、取播放地址、取歌词三个方法），
然后在 `MusicApi.init()` 里 `register(...)` 一行即可 —— UI、队列、同步、播放、歌词都不用改。

## 🆕 1.6.0_hotfix1 更新

### 修复：登录了网易云仍然放不了歌

**现象**：登录网易云成功（日志里有「网易云登录成功：CuteYue」），
但播放网易云的歌仍然报「已下架/版权受限」，登录好像完全没生效。

**根因**：客户端**无条件信任服务端下发的直链**。
而服务端可能只登录了 QQ（日志实证：服务端登录了 QQ，队列里却是网易云的歌）——
服务端解析网易云只能拿到「免登录外层地址」，对 VIP/下架歌会返回 404 网页。
**玩家本机登录的网易云账号（有自己的会员）完全没被用上。**

**修复：**

- 客户端**本机登录了某个平台**时，**忽略服务端直链，用本机账号解析**
  （本机账号的质量一定不比服务端差）
- 起播失败重试时：先用**本机账号**重解析原平台，还不行才跨平台兜底
- 登录成功后**立刻清掉直链缓存**并把当前这首重起播，不用重启游戏

### 修复：旧歌的后台线程会打断新歌

**现象**：刚跳过一首放不了的歌、新歌已经开始播了，却突然又被切走。

**根因**：旧歌的解析在**后台线程**跑，跑完时不检查「自己是不是还是当前这首」，
直接按自己的结论发 NEXT —— 把刚起播的新歌打断了。
日志实证：

```
[14:45:57] 起播《超能竞斗》→ 解码成功 → 已确认起播
[14:45:57] 【后台线程】起播失败《1》×2
[14:45:57] 收到状态 index=1 playing=false    ← 新歌被旧线程打断
```

**修复**：后台线程出结果后先校验 `isStillCurrent(key)`，过期就静默丢弃。

## 🆕 1.6.0 更新

### 新增：网易云音乐登录

- 设置页「登录方式」现在支持 **QQ / 微信 / 网易云** 三种
- 网易云用 **Cookie（`MUSIC_U`）** 登录：登录后可拿 **320kbps / 无损** 直链，
  部分「未登录返回 404」的歌也能正常放
- 两种平台的 Cookie **严格隔离**：网易云的凭证绝不会被拿去请求 QQ 的接口
- 服务端 `/symus login` 同样认网易云 Cookie（自动识别 `MUSIC_U`）

### 修复：主键盘上方的数字键打不出来

**现象**：在搜索框里想输入「123」「2024」这类内容，数字键却把页签切走了。

**原因**：`1`~`4` 是「切换页签」快捷键，而以前**不看焦点**——
不管你在不在输入框里打字，按下就先切页签。

**修法**：输入框有焦点时，快捷键主动让位，数字正常输入。
（输入框失焦后，`1`~`4` 依然可以切页签。）

### 修复：播放失败会无限重试

**现象**：某首歌的链接坏了（比如网易云下架歌返回 404 网页）时，
同一根坏链会被**每秒重试好几次**，持续好几分钟，全程没声音。

**原因**：常驻播放线程只判断「代次没变」，于是 `playOne()` 失败返回后
会被**立刻再调一次**（日志实证：5 分钟重试 418 次）。

**修法**：

- 一个请求只播一次（新增 `lastPlayedToken` 记账）
- 下载时校验 `Content-Type`：返回网页直接判失败，并给出「已下架/404」这种能看懂的原因
- 客户端识别失败后：清坏链 → **改从另一个平台找同名歌** → 连续失败才跳过
